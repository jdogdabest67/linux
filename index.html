3. Can one Joy-Con talk to both phone and Switch?

New experiment: investigate whether a Joy-Con can keep controlling the Switch while also sending its button presses to this phone, so ChatGPT can observe the inputs and help play.

Current reality: a Joy-Con normally pairs to one host connection at a time. The Switch does not provide a standard browser interface for sharing its live controller input with a phone.
Test A · Phone sees the Joy-Con: open the HID picker below and check whether Android/Chrome exposes the controller. If the Joy-Con is already connected to the Switch, it may not appear here.
Test B · Both at once: if the phone can see the Joy-Con, check whether the Switch still responds. Do not assume it works until both are observed responding at the same time.
If direct sharing fails: the likely next route is a separate controller bridge or a device that can relay inputs, or a human-in-the-loop test where ChatGPT chooses a move from a screenshot and you press it. This page alone cannot create that bridge.

Goal: find out what is genuinely possible with the hardware we have, not label a browser test as a working connection when it isn't.

9. PhantomHand serial packet lab

This reproduces the command framing found in PhantomHand's source code. It lets us encode and decode the same four-byte logical frame before any hardware connection exists. No USB/Bluetooth access and no commands are sent.

The frame is ASCII S (start), a two-byte payload (command ID + value), then ASCII E (end). PhantomHand's browser sends those as three USB transfers to an FT232 serial adapter.

Creating frame…

Known source-code concern: the Arduino parser treats every ASCII S and E byte as a delimiter, even if one appears inside a payload. The values 69 (0x45, ASCII E) and 83 (0x53, ASCII S) therefore collide with frame markers for stick commands.

Paste four hex bytes separated by spaces, such as 53 01 01 45. This decoder validates the framing and explains the command.

10. What the result means

Detected: only means the browser reports an API or a device in its chooser.
Not detected: does not mean the Joy-Con is broken. It may be connected only to the Switch, or Android may not expose it to this browser.
Even if the phone sees a Joy-Con, this page cannot automatically make the same Joy-Con send inputs to both the phone and Switch. We need an actual supported connection/bridge for that, and this test does not bypass Nintendo's controller pairing.

Privacy and safety: chooser actions require your tap. The interface and HID access tests may open a selected device, but they do not send controller commands or read input reports. The HID test only lists report-collection metadata and then closes the device.
